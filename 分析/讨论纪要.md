### 3.8 字数落差

样稿实际 5,727 / 10,026 / 8,281 字，题目写的 v0.5 是 **500–800 字**。（已向出题方确认：不是硬卡，「合理即可」。）

**结论：只出 `draft_v0_5.md` 一份，不出 `draft_full.md`。**

> 2026-08-01 修订：原方案是「出两份，full 版贴近样稿长度证明没丢精华」。撤销。

理由 —— 差距不是详略，是完成度：

| | 编辑要做的动作 |
|---|---|
| AI 给 8000 字 | 大部分是模型自填的过渡句、铺垫、正确废话，编辑要**删** |
| AI 给 800 字 | 每句都是判断和骨架，编辑往上**加**自己的理解 |

删比加累。而「把嘉宾口语写得过满、生成没有观点的正确废话」正是题目点名的失败模式，写长几乎必然踩上去。负责人原话是「形成**可编辑**的内容初稿」，不是「接近成品的稿」；v0.5 这个版本号也在说这事。

怕丢精华的正确解法不是写长，而是三份文件分工：

- `outline.md` 承载**全部**要点（不止 draft 用到的）
- `evidence.md` 承载**全部**证据原话
- `draft_v0_5.md` 只示范文风和最强的那条线

编辑拿这三份扩写到样稿长度，信息量大于一篇 8000 字 AI 稿，且没有废话要删。

## 5. 历史素材复用：完整方案

### 5.1 关键段表（增量入库）

历史笔记是静态的，**关键段只在入库时抽一次**，之后永久复用。

> 2026-08-01 补充：入库用的抽取逻辑与新文章的 outline 抽取是同一套，段表增量来源即 outline。见 §7.3。

```jsonc
// 段：只挂 note_id，不冗余元数据
{"seg_id":"note_03#04","note_id":"note_03","offset":[3120,3580],
 "text":"…","topic_tag":"幂律分布/中间层侵蚀"}

// 元数据：每篇一条，独立存放，随时可改
{"note_id":"note_03","标题":"…","日期":"2026-06-05",
 "适用读者":"…","可引用范围":"…"}
```

不在段上冗余元数据的理由：元数据会变（业务方可能收紧某篇的 `可引用范围`），冗余就得全表更新。

两层判断天然分在不同粒度：

- **篇级** → 合规约束（时效 / 可引用范围 / 读者），作用在 `note_id`
- **段级** → 内容匹配，作用在 `seg_id`

匹配到某段后拿 `note_id` 查回篇级约束，就知道"能用，但只能当框架不能引结论"。

### 5.2 匹配流程

每来一篇新文章，**一次调用**：

```
关键段表（8篇 ≈ 8k 字） + 逐字稿（12.7k 字） → 匹配结果
```

方向是**用历史的关键段去找输入文章**，不是反过来。理由：小对小，比拿特征词扫 37 万字既准又省。

**不做 RAG、不做 chunking、不做 embedding、不做 BM25。**

段表容量：单表能撑到**百篇量级**（预留 system prompt、输出和安全余量后保守估）。8 篇远未触顶。超过之后再分表或上 RAG——**那是规模问题，不是这一版的问题**。

### 5.3 同源识别交给 LLM，不写查重算法

> 2026-08-01 修订：原方案是「跑 8-gram Jaccard，>0.5 整篇排除」。撤销。

理由：阈值只在 note_02 这**一个**样本上验证过（0.925 vs 其余 0.000），换一篇改写过或部分重叠的同源笔记可能算出 0.3 就漏过去，无法保证覆盖率。而段表每篇才约 1000 字，LLM 拿它和逐字稿比对成本极低，且连改写过的同源也认得出。

§3.2 的实测数据保留，它是**发现 note_02 同源的过程记录**，不是流水线机制。

### 5.4 输出：判断与理由，不是 8 篇的解析报告

题目原文只要求「**至少 1 条**历史内容的复用建议，或明确说明为什么不应复用」。四种情况各有写法：

| 情况 | 输出 |
|---|---|
| 没匹配到 | 查了什么、按什么标准、为什么都不适用 |
| 匹配到但同源 | 拦截 + 相似度数据 |
| 匹配到但受限 | 有限复用 + **原文引用**它的 `可引用范围` 限制语 |
| 匹配到且可用 | 哪一段、放哪一节、怎么用、禁止怎么用 |

### 5.5 读者匹配：判，但不用它排除（原未定项 D，已结案）

**必须判**。PDF 只在字段说明里提了一句，但另两处是硬要求：

- README：「如存在…**适用读者不匹配**或引用范围不清，请在输出中明确标注需要编辑人工确认」
- content_brief：「如历史素材存在日期久远、**适用读者不一致**、引用范围有限或观点冲突，应明确说明不复用或仅有限复用」

**怎么判**：把 brief 的目标读者原文和该篇 `适用读者` 原文一起给模型，只答"有没有交集"。不定标签体系、不打分、不新增调用——挂在 §5.2 那次匹配调用的输出里加一个字段。

```
适用读者：AI行业从业者、创业者、投资人、科技公司管理者…
→ 一致（交集：创业者、管理者）
```

**为什么可以容忍模型判错**：实测 8 篇的 `适用读者` 与 brief 读者 **7/8 命中**（都是长串罗列，普遍含创业者/管理者/职场人）。唯一不命中的 note_02 已被同源检测拦掉（§3.2）。**这个字段在本数据集上零信息增益**，判定结果只写给编辑看，不触发任何自动排除，所以判错无害。

> 原想法是"要先定义标签体系才能编码"。撤销——不需要排除，就不需要可靠的排除机制。真正有约束力的是 `可引用范围`（见 §5.4），那是动作指令，原文抄出来即可。

## 7. 六个输出分别是什么

README 的文件名列表 = PDF 产出 3 的六条 bullet，一一对应，没有多余项也无需自行发挥：

| PDF 产出 3 原话 | 文件 | 数量约束 |
|---|---|---|
| 3 个内容标题/切入角度备选 | `angles.md` | **3，题目写死** |
| 一份文章结构与关键要点 | `outline.md` | 题目没给 |
| 关键观点对应的原始素材证据（逐字稿片段、段落编号或时间戳） | `evidence.md` | 跟着要点走 |
| 至少 1 条历史内容的复用建议，或明确说明为什么不应复用 | `reuse_suggestions.md` | **≥1，题目写死** |
| 一篇 500–800 字、可供编辑继续修改的内容初稿 v0.5 | `draft_v0_5.md` | 见 §3.8 |
| 需要编辑人工确认的事实、风险或缺失信息 | `editorial_checks.md` | 题目没给 |

### 7.1 `evidence.md` 是主表，其余是它的视图

抽取只跑一次，产出一张表 = `evidence.md`。其它文件不重复抽取，只做筛选与引用：

- `editorial_checks.md` = 筛 `类型=事实` 且无出处的行 + 转录风险项
- `outline.md` = 挑要点，引 `P` 编号
- `draft_v0_5.md` = 正文内联 `[13:32 嘉宾B]`
- `angles.md` = 从 evidence 挑角度，禁止碰原文（§9）

### 7.2 `evidence.md` 的结构：观点原话 + 印证原话，两部分

一条要点下，**观点原话**（他主张了什么）与**印证原话**（他拿什么支持这个主张）分开记。印证一行一条 —— 时间戳和说话人是跟着印证走的，塞进同一单元格就没法在 draft 里精确挂标记。

```markdown
### P09 杠铃效应：中间层被侵蚀
观点原话：「除非你处于该领域前1%…否则这种模式正在被侵蚀」（嘉宾B 00:26:04）

| # | 印证原话 | 说话人 | 时间戳 |
|---|---|---|---|
| 1 | 假如我是个文案写手，如果我水平一般… | 嘉宾B | 00:26:04 |
| 2 | 一方面是非常出色的"专才"在崛起… | 嘉宾B | 00:27:10 |
```

⚠️ **印证栏为空必须显式写"无"，不得省略。** 例：字幕 45「不适应的学校 10 年后将不复存在」是纯断言，全篇无佐证。空栏本身就是信号，决定这条能不能进 draft、要不要进 `editorial_checks.md`。

### 7.3 `outline.md` 并入段表，取消独立的入库步骤

新文章处理完的 outline，其形态（判断句 + 指回原文 offset）与 §5.1 的关键段表一致，可直接接进段表。于是**一套抽取逻辑，两个入口**：

- 历史 8 篇入库 → 跑抽取 → 段表（一次性）
- 新文章处理 → 跑同样的抽取 → outline → 接进段表（增量）

不用写两套代码。段表存判断句而非原文片段，对匹配也更有利（更短、噪音少）。

两个注意点：

- outline 里的**非复用节点**（引言、结语、过渡）接入前要过滤
- **接入时点不在本次 pipeline 内**。段表该存编辑定稿后的内容，不是 AI 初稿，所以这个动作发生在编辑改完之后。本版只负责把格式准备好

### 7.4 三份文件的区别：带不带证据、要不要取舍（原未定项 E，已结案）

按 PDF 产出 3 原话对齐：

| 文件 | PDF 原话 | 相对上游多了什么 | 要点取舍 |
|---|---|---|---|
| `evidence.md` | 关键观点对应的**原始素材证据** | — | 全部 |
| `outline.md` | 一份**文章结构**与关键要点 | 顺序与层级；**不抄原话**，只引 `P` 编号 | 全部 |
| `draft_v0_5.md` | 500–800 字内容初稿 | 取舍 + 文风 | 只挑最强的一条线 |

**outline 是全部要点，不是精选。** PDF 写的是"文章结构与关键要点"——观点句本身已经足够精炼，再筛一道就没有增量。且 §3.8 定的分工要求 outline 承载全部（含 draft 用不到的），编辑才有东西可扩。**做减法只发生在 draft 这一步。**

**取消所有数量上限**：

- 原「关键段不超过原文 10%」→ 撤销。段表存的是观点句不是原文片段（§7.3），跟原文字数不是一个单位；且一篇本来提炼不出那么多观点，上限不起作用，硬设反而会截断长笔记（最长一篇 8.3 万字）
- 原 §8.4「outline 要点数量未定」→ 同样不设上限，抽取自然收敛
- 两项一并从 §6 阈值声明表移除

## 8. 观点抽取（原未定项 A，已结案）

### 8.1 只调用一次，不分段

> 2026-08-01 修订：原想法是「分两遍读：先切 8–10 个话题段，再逐段抽」。撤销。

逐字稿 1.2 万字，任何模型一次读得下，分段没有收益，且会切断跨段关系 —— 字幕 36 的限定语限定的是字幕 38 的数据，划段极可能把两者分开，第二次调用就再也看不见。

### 8.2 类型标签用题目自己的词

题目已经把类型列好了，不需要自造，也不引用外部论文的分类体系：

> 产出 2：如何识别和保留关键**观点**、**案例**、**因果链**与原始**证据**
> 产出 3：需要编辑人工确认的**事实**、风险或缺失信息
> brief：**数据、外部机构、公司案例、岗位影响**等事实性说法，需要标注**核实状态**

标签 = **观点 / 案例 / 因果链 / 事实**，写在 `evidence.md` 的一列。打标签的唯一目的是分流到不同输出文件（见 §7.1），不在抽取时标，下游每个文件都得重判一次。

### 8.3 限定语挂成字段，不作为独立条目

§3.6 那三句（字幕 6 / 26 / 36）本身不是判断，是对别的判断的约束，单独抽出来下游无法使用。挂成被限定条目的字段，并立硬规则：**带限定语的条目，引用主张时必须同时带上限定语。**

### 8.4 要点数量：不设上限（2026-08-01 结案，见 §7.4）

题目全文只写死两个数字（3 个角度、500–800 字），未规定要点数量。曾试图用「500–800 字倒推要点上限」论证 8–12 条，但 500–800 只约束 `draft_v0_5.md`，而 outline 要服务编辑扩写到样稿长度，倒推不成立。**该论证作废。**

~~进 §6 阈值声明表，标为 MVP 默认值。~~ → 2026-08-01 改为**不设上限**，已从 §6 移除。理由见 §7.4。

### 8.5 切块只在段表一处

全流程唯一需要切块的环节：

| 环节 | 切块？ |
|---|---|
| 逐字稿抽取 | 否，全文一次进 |
| 历史笔记入库（段表） | **是**，按整句边界切 |
| 段表 × 逐字稿匹配 | 否 |
| 同源识别 | 否，LLM 判断（见 §5.3） |

段表切段必须按标点切出的整句，不能让模型自由划字符区间 —— 自由边界的标注一致性极低（ViClaim 数据集实测 Krippendorff α < 0.2，数据作废），已改用句子级。

字幕 53 的口播是另一回事：不是切块，是让模型把口播那句原文抄出来写进 `editorial_checks.md` 的风险项，不需要切分算法。

### 8.6 转录存疑不猜，直接标

字幕 85 说话人归属存疑（§3.4）→ 写进 `editorial_checks.md`，对应题目「风险或缺失信息」。原则：能消歧就消歧，消不了就标记，不硬猜。

### 8.7 片头剪辑排除，靠 prompt 不靠算法

播客片头会把后面的精彩片段剪到开头做钩子。本篇的片头是字幕 1–7（00:00:00–00:01:07），字幕 8 主持人问「您现在经营着好几家公司，您看到了什么？」才是正片开始。

实测对应关系：字幕 2 ← 字幕 57（27:42）、字幕 1 ← 字幕 31（08:58）、字幕 4 ← 字幕 11（02:09）、字幕 5/7 ← 字幕 39（14:29）。

**规则：片头不作为证据，证据一律指向正片对应位置。**

做法是在抽取 prompt 里写明，不写检测算法——片头在结构上一眼可见（开头几条都是断句，互相不接，没有问答流），模型一次读完全文自己认得出。

> 2026-08-01：曾提议用 containment（重合÷较短者）检测片头。撤销——为模型顺手能做的事写集合运算，属于自找麻烦。

顺带一个可讲的点：字幕 6 那句「未来三年大量白领岗位会被 AI 替代」**就在片头里**——最抓眼球的话本来就是为效果剪进预告的，而说话人自己在同一句里声明了"我还没有看到明确证据"。

## 9. 角度从哪来：只喂 evidence，不喂原文（原未定项 B 的一半）

> 排序问题仍未定，见第二部分 B。这里只定"角度从哪来"。

**规则：生成角度时输入 `evidence.md`，不输入逐字稿原文。**

理由 —— 把整篇原文丢给模型让它"提炼角度"，等于让它自己找重点。它做不到取舍，只能取平均，输出全篇的最大公约数，也就是那句正确的废话（"AI 不会取代你，会用 AI 的人会"）。**平庸是这个操作本身决定的，不是提示词写得不好。**

`evidence.md` 已经是做完取舍的结果：判断句、带说话人、带时间戳、带限定语字段、印证栏空的一眼可见。喂它进去，模型不用再找重点，只需要在给定落点上选和写。

> 这与实践经验一致：给 AI 一份**厚 brief** 生成的内容，质量明显高于把整篇文章塞进去让它自己读——厚 brief 的重点是人挑好的。区别在于这里的厚 brief 由 pipeline 自己产出，不用手写。

三个附带结论：

- 又一处印证 §7.1「`evidence.md` 是主表，其余是它的视图」——`angles.md` 也是它的视图
- 角度的证据溯源天然成立：角度引的是 `P` 编号，`P` 编号本来就挂着时间戳
- 抽取质量直接决定角度质量。evidence 抽漏的东西，角度阶段再也找不回来

### 9.1 排序交给 LLM，但不打分（原未定项 B 的另一半，已结案）

3 个角度全部交付给编辑，最终选择权在人，**排序错了代价很低**，不值得为它设计规则或评分机制。

**唯一约束：让模型直接输出排好序的 3 个 + 各自理由，不要输出分数。**

理由：LLM 对创意做绝对打分校准很差（Si et al. 2024 实测，直接打分 50.0–51.7%，低于人类评审一致性 56.1%），且存在 verbosity bias（写得长的得分高）。更实际的问题是——**一旦给了分数，编辑就只看分数，理由白写了。**

> 原顾虑是"模型生成角度再让模型打分＝循环自评"。这个顾虑成立，解法不是换排序机制，是**不打分**。

## 10. `editorial_checks.md` 收什么（原未定项 C，已结案）

### 10.1 不加规则捞取层

原想法是"正则先捞含数字/比例/年份/机构的句子，模型再判有没有出处"。撤销。

**规则捞的是"长得像事实的句子"，该核的是"没出处的断言"，两者不重合。** 字幕 45「不适应的学校 10 年后将不复存在」没数字没机构，正则捞不到，但它是全篇最该核的一条。

### 10.2 三类，对应题目原话

题目原话：「需要编辑人工确认的**事实、风险或缺失信息**」。

| 分类 | 收什么 | 来源 |
|---|---|---|
| 事实 | 无出处的数据 / 机构 / 案例 / 岗位影响 | 规则：类型=事实 ∧ 印证栏空 |
| 风险 | 争议观点、脱敏遗漏 | LLM 判 |

⚠️ 第三类题目写的是「缺失信息」，这里改叫「存疑信息」——转录错字既不是缺失也不是风险，无处安放。**交付物中须写明对应关系**：「存疑信息（含题目所指的缺失信息，另收录转录疑误）」。

### 10.3 印证栏为空只对"事实"有效
