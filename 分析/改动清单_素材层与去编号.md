# 改动清单：素材层与去编号

> 讨论结论,给重构者看的执行说明。写于 2026-08-02,同日据第二轮讨论修订。
> 读这份之前不需要读别的,背景都在第一节。

---

## 〇、为什么要改

编辑拿到当前这套 6 份输出,**没法把 1630 字的初稿写成成稿。**

三个数据把问题定住:

1. **成稿是压出来的,不是扩出来的。** 已发布样稿 5708 / 9766 / 8175 字,源头都是一场一小时上下的演讲或访谈,逐字稿本身就上万字。压缩比约 **1.3 : 1**。本次逐字稿 12677 字,做成笔记侠标准的整理稿,量级本来就在 8000 上下 —— **素材一直是够的。**
2. **但当前 pipeline 在第一步就丢了 80%。** 97 条字幕,渲染进 `outputs/*.md` 的只有 **19 条不同字幕**(算上中间产物 JSON 也只有 26 条),**78 条从头到尾没在任何编辑能看见的文件里出现过**。编辑连"被丢掉了什么"都看不见。
3. **压缩发生的层级错了。** 笔记侠整理稿做的是**句子级压缩**(去口水、合并重复、口语转书面),判断基本全留;当前 pipeline 做的是**观点级压缩**(97 条字幕只留 16 个判断)。这是两种活。

所以:**不做 `draft_full`。** 加长初稿的起点还是那 16 条,只能加水,而且撞 README §六.4 自己那条论证(「AI 给 8000 字大多是过渡句,编辑要删,而删比加累」)。

要补的是**初稿下面那一层素材**,以及**去掉文件之间的编号指代**。

一句话概括工具的价值定位(可用于 README 改写):

> 编辑最花时间的从来不是"读懂访谈",是**把时间序的一万三千字重排进文章序,并判断哪些是判断、哪些是血肉、哪些可弃**。工具的价值在这个重排上,不在替编辑读。

## 一、`evidence.md` 每条要点挂完整片段

**为什么**:现在每条要点只摘 1–2 句支撑,那是**证明用量**,不是**写作用量**。
P15 杠铃效应在逐字稿里嘉宾讲了约 3 分钟七八百字(文案写手的例子、专才和通才两个角色的展开),`evidence.md` 里只有 100 字。够证明它站得住,不够写成成稿里的一节 —— 编辑必须回逐字稿。

**改什么**:每条要点除现有的「观点原话 / 限定语 / 支撑表」外,增加一段**完整片段**。

**关键约束**:片段正文**由代码从 SRT 取,不由模型复述**。模型只输出一个字幕号集合,代码按号回填原文。理由同 README §六.1 —— 让模型抄一遍只会引入错字,且破坏溯源。

> **字段名用 `cue_ids`,不要用 `segment_ids`。** 仓库里 `segment` 已经被同源笔记的段表占了(`store/segments.jsonl`、`prompts/segment.md`、`matched_segments`、`config.segments_per_note`),再拿它指字幕会把模型和后来的人都绕进去。`pipeline/srt.py` 里字幕单位本来就叫 cue。

**碰的文件**:
- `prompts/extract.md` —— 让模型为每条要点额外输出 `cue_ids`(字幕号数组)
- `pipeline/validate.py` —— 校验 `cue_ids` 都在 SRT 实际范围内
- `pipeline/render.py` —— 渲染完整片段
- `pipeline/srt.py` —— 若无按号取原文的函数则补一个

**验收**:随机抽 3 条要点,片段文字与 `data/interview_transcript.srt` 对应条目**逐字相同**。

**代价**:`evidence.md` 会明显变厚。这是对的,它是编辑动笔前的查证面。

## 二、新增 `outputs/material_map.md`

**它是什么**:一份**去噪后的完整脉络**。相当于逐字稿,但按文章序重排、按章节归好组、去掉了寒暄口误广告。编辑写稿时手边翻的就是这一份 —— 所有增量信息都在里面。

**和 evidence 的关系:允许重复,不做零重叠。**

第一轮曾定过 material_map「只装未进稿的、两边零重叠」,**这条废弃**。零重叠会逼编辑写第三节时在两个文件间来回翻(判断的论证在 evidence,案例细节在 material_map),跟第三节「去掉跳转」的原则自相矛盾。material_map 里**已进稿和未进稿的材料都要有**。

两份文件是**两根不同的轴**,重复是应该的:

| 文件 | 组织轴 | 覆盖面 | 什么时候看 |
|---|---|---|---|
| `evidence.md` | 按**要点** —— 一条判断带它的完整论证 | 只有进了稿的那 16 条 | 动笔前查:这条站不站得住、原话有多少 |
| `material_map.md` | 按**章节** —— 一节里所有能用的材料 | 整场访谈,已用 + 未用 | 动笔中翻:这一节我还能写什么 |

**内容**:按 `outline.md` 的章节分组,**粒度分到「三.2」这一层,不是只分到「三」** —— 否则一节底下堆几千字,编辑还是得自己找。

**格式**(组头是材料标签,底下是证据行):

```
## 三、职业结构正在从稳定的中间层转向杠铃两端

### 三.2 前1%专才与高能动通才成两极

**杠铃效应的完整论证过程**
[54] 00:26:04 嘉宾B
> 我的假设是,你将会看到一种"杠铃效应"。这正是我们在某在线
> 课程平台上所观察到的:有一群人正在成为专家。……

**嘉宾A 当场附议:两条路线都要有能动性**
[55] 00:27:32 嘉宾A
> 无论是走专才路线还是通才路线,你们都有能动性。
```

**模型输出什么**:同 §一 —— 只输出**标签 + `cue_ids`**,正文一个字都不写,由代码按号去 SRT 抠原文回填。

> 字幕号本来就在输入里,但"哪几条该归成一组、这组叫什么名"只有模型能定,这是它唯一的活。

**三条硬约束,少一条都会翻车**:

1. **组头是「材料标签」,不是「要点」。** prompt 里必须写死这个区分。没被 extract 抽中的那些字幕**大多本来就不是判断**,那正是它们没被抽中的原因。不点破的话,模型会照 `extract.md` 的老规矩去造判断,造出一堆"AI 是把双刃剑"—— 而 `extract.md` 里专门有硬性排除这类的条款。**这一层只做归类和命名,不做主张。**
2. **一组材料可以绑一组不连续的字幕号。** 空间智能这个主题实际散在 **32、33、67、68、74、75**,从第 9 分钟横跨到第 39 分钟,中间隔着别的话题。只支持连续区间就框不住它。
3. **不切,只框。** 单位仍是字幕号(代码定,一个字不动),允许区间重叠、允许一条字幕带多个标签、允许字幕哪儿都不属于。

   为什么不做语义切分:字幕最短 3 字、中位 81 字、最长 419 字,不是稳定单位 —— 字幕 51 结尾是半句话("现在有了更有效的"),字幕 53 里前半段是主持人念广告、末句却是引出 P15 的关键提问。但**改成"框"之后这些坑自己就没了**:框成 `[50–52]`,半句在区间内部;53 整条标两个标签(`广告可弃` + `末句引出杠铃效应`)。而按语义切分会让边界由模型决定,直接撞 README §六.1。

**覆盖情况怎么交代**:在 `material_map.md` 顶部渲染一行统计,给编辑看,**不做成 `check.py` 的红绿灯**:

```
97 条字幕:已收录 78 条 / 判为可弃 15 条(广告、寒暄、口误,逐条列在文末)/ 未归类 4 条
```

> 之前写的验收标准是「应覆盖 SRT 绝大部分」。这条不可执行 —— `check.py` 每一项必须是代码能算真假的布尔,"绝大部分"不是。
> 而且这不是题目要求的东西:PRD §3.7 那 12 项验收挂在 D4「**假设**由主编辑验收」下面,是我们自拟的。所以覆盖率就地渲染给编辑看即可,不必为一个自定阈值卡红灯。
> **但"可弃的必须显式列出"这条保留** —— 不能静默丢掉,那是这份文件存在的意义。

**碰的文件**:
- 新增 `prompts/material_map.md`
- `run.py` —— `STAGE_ORDER` 现为 `["extract", "reuse", "angles", "outline", "draft"]`,在 `outline` 之后加 `material_map`(依赖 outline 的章节结构)
- `pipeline/render.py` —— 新渲染函数(含顶部统计行)
- `pipeline/validate.py` —— 校验 `cue_ids` 都在 `[1, 97]` 内;**不校验与 evidence 是否重复**(重复是允许的);有效号 + 可弃号是否覆盖全集只作提示,不 raise

**编辑动线**变为:

```
angles 选 → outline 搭 → evidence 查 → draft 写 → material_map 扩 → reuse 补 → checks 核
```

`evidence` 是**动笔前**查的,`material_map` 是**动笔中**翻的。

## 三、去掉 outputs 之间的 P 编号指代

**为什么**:编辑看到 `P14` 得先想"去哪翻",翻到了还得再读一遍才知道是什么。**有问题就地说明,别在文件之间指代。**

**原则**:P 编号有两个身份,拆开处理。

| 身份 | 处置 |
|---|---|
| 给代码的连接键(`point_id`,下游 validator 靠 `valid_pids` 校验) | **保留,不动** |
| 给编辑的导航 | **删,不渲染进任何 `outputs/*.md`** |

**⚠️ 只改渲染层,不要动 `point_id` 本身**,`pipeline/validate.py` 里 `validate_reuse` / `validate_angles` / `validate_outline` 都依赖它。P 编号只存在于 `outputs/_intermediate/*.json`。

**逐个文件**:

| 文件 | 现状 | 改成 |
|---|---|---|
| `outline.md` | **结构和要点的写法保持不动,现在这样就是对的**;只删每条后面挂的 `` `P01` ``,以及顶部那句「`P` 编号对应 `evidence.md`」 | 删掉编号即可。编辑看 outline 是为了知道播客讲了什么、自己怎么下笔,要点级锚点不需要 —— 章节标题和 material_map 是对齐的,翻同名那节就行 |
| `outline.md` | 末行「未进入本结构的要点:`P09`、`P10`、`P11`、`P13`」 | 把四句话写出来:终生收入下降超五分之一 / 教育成本约 100 美元 / 用 AI 学习省 60% 时间 / 不适应的学校十年后不复存在 —— 四条都是无出处的事实性说法 |
| `draft_v0_5.md` | `[P01 字幕11 00:02:09 嘉宾B]` | `[字幕11 00:02:09 嘉宾B]` —— 零损失,字幕号本来就是更硬的锚,且指向逐字稿而非另一个 output |
| `editorial_checks.md` | 表格首列是 `pid` | 每条自带原话 + 说话人 + 字幕号 + 为什么要核,自足 |
| `angles.md` | 引 P 编号 | 直接写支撑这个角度的判断是什么 |
| `reuse_suggestions.md` | `剔除… {point_id}` | 写出被剔除的是哪条内容 |
| `material_map.md` | (新文件,别引) | 章节标题与 outline 文字对齐即可 |

**碰的文件**:`pipeline/render.py` 为主(约 45、66–69、104–133、181–184、317–318、395–402、513 行);各 `prompts/*.md` 里的输出示例同步改。

**代价**:同一句原话会在 evidence 和 editorial_checks 里各出现一次,文件都变长。**这是故意用冗余换掉跳转**,对编辑当天要用的东西这笔换划算。
