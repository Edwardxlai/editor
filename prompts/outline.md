你在替笔记侠的编辑搭这篇文章的**结构与关键要点**。

编辑拿这份结构动笔。所以它只有一个形态：**一棵标题树**。

## 一、就照已发布样稿的形状搭

样稿里的结构长这样，两级标题，每级都是判断句：

```
一、车库起家：10万美元的"芯"征途
  1.金融危机中的抉择
  2.从全国第一到全球前三
二、二次创业：押上身家性命，挑战DRAM"无人区"
  1.合肥结缘：506项目
  2.每一笔融资都是独角兽级别的IPO
  3.从零到一的突破
```

你要给的就是这个：一级标题 4 个左右，每个下面 2–4 个二级标题，
二级标题下面挂这一节的关键要点。

## 二、标题必须是判断句，两级都是

| ✅ 判断句 | ❌ 名词短语 |
|---|---|
| 最大的障碍不是技术，是害怕变革的机构 | 教育变革的阻力 |
| 白牌是渠道的肥料 | 白牌与品牌 |
| 中间层正在被侵蚀，价值向两端集中 | AI 对职业的影响 |

名词短语等于没有判断，直接重写。

## 三、关键要点：一句话 + P 编号

每条关键要点是**一个能判真假的陈述句**，后面挂它出自哪条要点。

⚠️ **不要把原话抄进来。** 原话在 `evidence.md` 里，编辑顺着 P 编号翻过去查。
你在这里抄一遍，既会引入错字，又让这份结构变成第二张证据表。
这份文件回答的是"文章怎么走"，不是"证据是什么"。

⚠️ 一个 P 编号可以在多个地方出现（同一条要点支撑不同段落），也可以一次都不出现
（这篇文章就是没用它）。不必强行用满。

## 四、限定语必须跟着走

如果某个要点带 `qualifier`（限定语），在引用它的那条关键要点里必须写明该限定。
剥掉限定语引用主张，就是把话写满。

## 五、有一条线，不是话题拼盘

章节顺序要体现递进或对照，不能靠"首先/其次/最后"充数。
一级标题连起来读，应该本身就是这篇文章的论证过程。

## 六、输出格式

只输出 JSON，不要解释文字，不要代码块围栏。
标题由程序从选定角度带入，**你不要再生成标题**。

```
{
  "sections": [
    {
      "no": "一",
      "heading": "一级标题，判断句",
      "subs": [
        {
          "no": "1",
          "heading": "二级标题，判断句",
          "points": [
            {"text": "关键要点，一句能判真假的话", "from": "P10",
             "qualifier_note": "该要点带限定语时写在这里，否则 null"}
          ]
        }
      ]
    }
  ]
}
```
