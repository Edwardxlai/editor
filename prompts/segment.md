你在为笔记侠建历史笔记的**关键段表**。

段表的用途只有一个：将来有新素材进来时，用这张表去匹配新素材，找出"我们以前写过相关的"。
所以段表要**短、是判断、噪音少**，它不是这篇笔记的缩写版。

## 规则

1. 每一段输出两样东西：
   - `claim`：**一句判断句**，说清这段在主张什么。这是将来用来匹配的东西。
   - `quote`：支撑这个判断的**原文**，必须**一字不改**地从正文里摘，且**落在整句边界上**
     （从一句话的开头到句号/问号/感叹号结束，不能从半句开始或半句结束）。

2. `quote` 长度 40–200 字。太短没信息，太长就成了抄全文。

3. 只抽**可复用**的内容：判断、案例、方法、数据。
   **不要抽**：寒暄、过渡、主持人串场、"我们今天请到了…"、目录式的关键词罗列。

4. 本篇最多抽 **%%SEG_CAP%%** 段。
   ⚠️ 这是 MVP 临时占位值，无业务依据。**宁缺毋滥**——抽不满不是问题，
   把段表写成缩写版全文才是问题。

5. `topic_tag`：2–8 字的主题标签，用于人快速扫读，例如「幂律分布/中间层侵蚀」。
   **同一篇内 topic_tag 不得重复。** 同一个主题只保留最有信息量的那一段——
   重复的标签说明你在把一个观点拆成几条，这对匹配没有任何帮助。

6. 每条 `claim` 必须**独立成立**：脱离原文单独读，也是一个完整的判断。
   ❌ 反例：「具体性是筛选知识的标准」「判断结果的能力对所有人是公平的」
   —— 这种句子离开上下文就没有意义，匹配时也命中不了任何东西。

## 输出格式

只输出 JSON，不要解释文字，不要代码块围栏。

```
{
  "segments": [
    {
      "claim": "一句判断句",
      "quote": "从正文一字不改摘出的整句原文",
      "topic_tag": "主题标签"
    }
  ]
}
```

注意：**不要输出字符偏移量**。偏移量由程序用 `quote` 在原文里定位算出 —— 
你给的偏移量无法被校验，程序算的可以。

## 关于逐字准确

程序会拿你给的 `quote` 到原文里做定位，**定位不到的段会被直接丢弃**。
所以你不需要在心里反复核对某句话是不是一字不差 —— **直接从原文复制粘贴即可**，
校验由程序做。把精力花在"挑哪几段"上，不要花在自我核对上。
